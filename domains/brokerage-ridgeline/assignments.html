New to SQL? Start Here

A step-by-step guide for your first day. Follow the five steps in order; each one takes about 10 minutes.

  1. 1

    Install the free tools

    You need two free programs from Microsoft:

    • SQL Server (Express or Developer edition): the database itself. Download SQL Server
    • SQL Server Management Studio (SSMS): the program where you type and run SQL. Download SSMS

    Choose the default options during installation. When SSMS asks you to connect, use server name localhost (or .\SQLEXPRESS for Express) and Windows Authentication.

  2. 2

    Create your practice database

    1. In SSMS, click New Query (top toolbar).
    2. Type CREATE DATABASE RidgelinePractice; and press F5 to run it.
    3. In the database drop-down on the toolbar (it usually says master), choose RidgelinePractice.

    Always check that drop-down before you run anything. Running in master is the most common beginner mistake.

  3. 3

    Load the Ridgeline data

    1. In SSMS choose File → Open → File and open data_setup.sql.
    2. Make sure RidgelinePractice is selected, then press F5.
    3. At the bottom you should see a small table of row counts: Clients 100, Securities 50, BrokerageAccounts 100, TradeOrders 240, Executions 304.

    Run it only once. If you run it again it stops with a message, because the tables already have data. That is expected.

  4. 4

    Run your first query

    Open a new query window and type this exactly, then press F5:

    SELECT TOP (5) AccountID, AccountName, Region
FROM brokerage.BrokerageAccounts;

    You should see 5 accounts, starting with 1 · Olivia Bennett - Individual · North. That means everything is working.

    • SELECT lists the columns you want.
    • FROM brokerage.BrokerageAccounts names the table: brokerage is the schema (a folder), BrokerageAccounts is the table.
    • TOP (5) returns only the first 5 rows.
  5. 5

    Answer your first question

    Every question card on this page has the same parts:

    • The ID, such as DQL-B03: topic DQL, level B (Beginner; I is Intermediate, A is Advanced), question 03. Put this ID above your answer when you submit.
    • The title and task: what the result should show.
    • Check expected result: press it after you have run your own query, to compare the number of rows and the values.
    • Done: tick it to track your progress (saved in this browser).

    Start with Introduction, then DQL: SELECT Basics. Use the Beginner button on the level slider to see only the easy questions first.

Help and answers to common questions

I'm stuck on a question. What should I do?
  1. Read the question again and write down which columns it wants and from which tables.
  2. Start small: SELECT * FROM brokerage.TableName; to look at the data.
  3. Add one part at a time: first FROM, then WHERE, then GROUP BY, then ORDER BY. Run after each step.
  4. Use the search box to find similar questions on the same keyword (for example GROUP BY or LEFT JOIN).
  5. Still stuck after 15 minutes? Note the question ID and ask your instructor.
What do common error messages mean?
Error messageWhat it usually meansHow to fix it
Invalid object name 'brokerage.BrokerageAccounts'Wrong database selected, or the data was not loadedChoose RidgelinePractice in the drop-down; run data_setup.sql
Invalid column name 'X'Spelling mistake, or the column is in another tableCheck the table guide below for the exact name
Ambiguous column name 'AccountID'Two joined tables both have that columnPut the table alias in front: p.AccountID
Column '…' is invalid in the select list because it is not contained in … GROUP BYYou selected a column that is not grouped or aggregatedAdd it to GROUP BY, or wrap it in SUM / COUNT / MAX
Incorrect syntax near '…'A typo, a missing comma, or a missing bracketLook just before the word in the message
Conversion failed when converting …Text and numbers or dates are being mixedUse CAST or TRY_CAST, and check the values
The INSERT / UPDATE / DELETE statement conflicted with the … constraintA rule in the table blocked your changeExpected in Constraints questions; read which rule it names
My query is different from the expected result. Is it wrong?

Not necessarily. Compare the number of rows and the values. If they match, your query is correct even if it is written differently. If the question has no ORDER BY, your rows may come back in another order; that is fine.

I changed or deleted data by mistake. How do I get it back?

Create a fresh database (for example RidgelinePractice2), select it and run data_setup.sql again. Questions in the DDL, Constraints and DML topics change the data, so it helps to keep a second practice database just for them and reload it whenever you want a clean start.

Useful SSMS keyboard shortcuts
  • F5: run the query (or only the highlighted part, if you select some text first).
  • Ctrl + N: new query window.
  • Ctrl + R: show or hide the results pane.
  • Ctrl + K, then Ctrl + C: comment out the selected lines. Ctrl + K, Ctrl + U: uncomment.
  • Ctrl + Shift + R: refresh IntelliSense after you create a table.
Words you will see (glossary)
Table
A set of rows and columns about one thing, such as BrokerageAccounts.
Row / Column
A row is one record (one account). A column is one piece of information (the account's region).
Schema
A folder for tables. All Ridgeline tables are in the brokerage schema.
Primary key (PK)
The column that uniquely identifies each row, such as AccountID.
Foreign key (FK)
A column that points to a row in another table, such as TradeOrders.AccountID.
NULL
An empty or unknown value. Test it with IS NULL, never = NULL.
Query
A SQL statement that asks for data, usually starting with SELECT.
Join
Combining rows from two tables using a shared column.
Aggregate
A function that summarises many rows into one value: COUNT, SUM, AVG, MIN, MAX.
Trade order
One row in TradeOrders: a trade order at Ridgeline. RoutingCategory is A, B or C, and WorkflowStatus is Open, Closed or Pending.

Before You Start

Set up your practice database once, learn the five tables, then work through the questions.

1Set up the database

  1. In SQL Server Management Studio, create a new database (for example RidgelinePractice) and select it.
  2. Open data_setup.sql from the brokerage folder and run it once. It creates the brokerage schema with 100 clients, 50 securities, 100 brokerage accounts, 240 trade orders and 304 executions.
  3. DDL, Constraints and DML questions change the data. Run data_setup.sql again in a fresh database when you want to start clean.

2The tables

ClientsClientID (PK), ClientName, ClientReference, Email
SecuritiesSecurityID (PK), SecurityName, Symbol, AssetClass
BrokerageAccountsAccountID (PK), AccountName, AccountNumber, Region, ClientID
TradeOrdersOrderID (PK), AccountID, OrderReference, RoutingCategory (A · B · C), WorkflowStatus (Open · Closed · Pending), EstimatedValue, RequestedQuantity, OrderDate, SubmittedAt, RecordedAt, Note, BackupNote, ParentOrderID, SecurityID, Side
ExecutionsExecutionID (PK), OrderID, ExecutionReference, ExecutedQuantity, ExecutionPrice, ExecutedAt

3How to practise

  • Start with Beginner, then Intermediate, then Advanced. Use the level slider to focus.
  • Write and run your own SQL first. Then press Check expected result to compare the row count and values.
  • A different query can still be correct. If there is no ORDER BY, your rows may come back in another order.
  • Tick Done to track your progress. It is saved in this browser only.

4How to submit

  • Save one .sql file per topic, named TOPIC_YourName.sql, e.g. JOINS_PriyaSharma.sql.
  • Put the question ID above each answer as a comment, e.g. -- JOINS-B03.
  • Under each query, note how many rows it returned.
  • For "explain" questions, write your answer as a comment.
